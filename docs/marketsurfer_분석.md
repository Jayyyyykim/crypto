## 2. 가져올 가치가 큰 것 4가지

### ① 매매환경을 느린 봉으로만 판정한다 ⭐️

사이트가 화면에 그대로 써 둔 규칙:

> "매매환경 판정은 **일·3일·주·월** 네 봉으로 봅니다. 그중 **3개 이상**이 같은
> 방향이면 정렬로 봅니다. **4시간·12시간을 빼는 이유는**, 매매환경 판정이
> 장중 움직임 하나에 뒤집히면 판정으로 쓸 수 없기 때문입니다."

이건 지금 봇의 `mtf_score.py`와 정면으로 다르다. mtf_score는 6봉을
25:20:18:15:12:10으로 가중해 한 점수로 뭉갠다. 4H·12H가 22점 —
장중 한 번 출렁이면 총점이 22점 움직여서 "상승 우위(65)"가
"방향성 없음(43)"으로 뒤집힌다. **환경 판정으로 못 쓴다.**

역할을 나눠야 한다:
- 환경 판정 = 느린 봉 4개만 (하루에 한 번 바뀔까 말까)
- 진입 타이밍 = 6봉 전부 (mtf_score 그대로 유지)

→ `regime_gate.py`로 구현.

### ② 진입이 아니라 '사건'을 센다 ⭐️⭐️ (가장 중요)

지금 봇의 승격 게이트는 "4주 + 30건"이다. 그런데 `detect_core_signal()`은
'일봉 지지 0.5% 이내 + 4H 상승 + RSI 과매도'가 동시에 맞아야 발화한다.
`/페이퍼진단`이 직접 인정한다 — *"횡보장엔 며칠씩 0건일 수 있어요 (정상)."*

**30건으로는 아무것도 증명되지 않는다.** 승률 55%와 45%를 30표본으로
구분할 수 없다 (표준오차 ±9%p).

사이트는 이 문제를 다르게 풀었다. 진입을 세지 않고 **셋업 사건**을 센다.
종목마다 매일 "전일 고점을 돌파했나 / 아래쪽 유동성이 쓸렸나 / 구간
어디에 있나"를 기록하고 1일·3일·주 뒤 자동 채점 → 표본 1,833건.

→ `setup_ledger.py`로 구현. 여기에 **과거 봉 소급 채점(backfill)**을 더해서
4주를 기다릴 필요조차 없게 했다. 오늘 돌리면 오늘 수천 건이 쌓인다.

### ③ 지지·저항이 봉당 1개가 아니라 1·2·3차 + 관성 무효화가

지금 봇의 `analyze_timeframe()`:

```python
"support"    : recent_low     # 최근 20봉 최저가
"resistance" : recent_high    # 최근 20봉 최고가
```

레벨이 봉당 딱 하나고, 그마저 '20봉 극값'이라 한 번 찍고 만 꼬리에도 잡힌다.
그런데 `detect_core_signal()`은 **이 레벨 0.5% 이내에서만 발화한다.**
레벨이 부실하면 신호도 그만큼 부실하다 — 페이퍼가 0건이거나 자꾸 털리는
원인이 전략이 아니라 여기일 수 있다.

→ `level_map.py`: 프랙탈 피벗 → 근접 병합(터치 횟수 누적) → 거리순 1·2·3차,
   그리고 "이 읽기가 틀렸다고 인정할 가격"(관성 무효화가)까지.

### ④ 다음 봉 예상 범위

손절 폭이 한 봉 예상 범위보다 좁으면 **신호 품질과 무관하게 털린다.**
지금 봇엔 이 sanity check가 없다.

→ `expected_range.py`. 단, 대칭 ATR 밴드가 아니라 **위/아래 이탈폭을 따로**
분포로 만들었다 — 코인은 아래 꼬리가 길어서 대칭 밴드는 하단을 항상
과소평가하고, 그 밴드로 손절을 잡으면 그만큼 자주 털린다.

## 3. ⚠️ 사이트 숫자를 그대로 믿으면 안 되는 이유

사이트가 공개한 3일 기준 채점표:

| 셋업 | 표본 | 적중률 | | 셋업 | 표본 | 적중률 |
|---|---:|---:|---|---|---:|---:|
| 디스카운트 구간에서 | 326 | **81.9%** | | 프리미엄 구간에서 | 189 | **37.0%** |
| 아래쪽 유동성 쓸린 뒤 | 405 | **74.8%** | | 위쪽 유동성 쓸린 뒤 | 468 | **26.3%** |
| 전일 고점 돌파 뒤 | 226 | **69.5%** | | 전일 저점 이탈 뒤 | 219 | **28.3%** |

왼쪽은 전부 '상승' 방향 셋업, 오른쪽은 전부 '하락' 방향 셋업이다.
왼쪽은 죄다 69~82%, 오른쪽은 죄다 26~37%. **각 쌍이 대략 100%로 합쳐진다.**
그리고 사이트가 같이 표기한 전체 방향 적중률은 **53.6%** — 동전던지기다.

이건 셋업이 좋아서 나올 수 있는 모양이 아니다.
**표본 기간에 시장이 올랐다**는 뜻이다. 상승 드리프트가 있는 구간에서
'상승 셋업'을 채점하면 뭘 골라도 70%가 나온다.

### 재현해봤다

`demo_edge.py`는 **예측력이 정확히 0인 합성 계열**(드리프트 얹은 랜덤워크)에
똑같은 채점을 돌린다. 종목 40개 × 400봉:

```
 기준선 — 아무 날이나 잡았을 때:  상승 73.0%  하락 27.0%   (표본 13,038건)

 셋업                    방향      표본     적중률    기준선      초과
 전일 저점 이탈 뒤         하락    2,452    28.3%    27.0%    +1.2%p
 위쪽 유동성이 쓸린 뒤      하락    3,168    27.7%    27.0%    +0.7%p
 프리미엄 구간에서         하락   11,258    26.4%    27.0%    -0.6%p
 전일 고점 돌파 뒤         상승    6,339    73.8%    73.0%    +0.8%p
 아래쪽 유동성이 쓸린 뒤    상승    3,144    72.6%    73.0%    -0.3%p
 디스카운트 구간에서       상승      865    72.4%    73.0%    -0.6%p
```

사이트 표(69.5 / 74.8 / 81.9 vs 26.3 / 28.3 / 37.0)와 **거의 같은 자리**다.
그런데 이 계열엔 예측할 구조가 아예 없다. 초과 적중률은 전부 ±1%p 안이다.

**결론: 적중률 칸만으로는 셋업의 실력과 시장 방향을 구분할 수 없다.**

### 그래서 우리 구현은 두 칸을 더 낸다

1. **기준선(baseline)** — 같은 기간·같은 horizon에서 아무 날이나 잡았을 때의
   상승/하락 확률. 무조건부 전방 수익률로 직접 계산한다.
2. **초과 적중률(edge) = 적중률 − 기준선.** 이게 진짜 값이다.

여기에 환경 라벨을 사건마다 붙여 저장하므로,
*"디스카운트 롱은 상승국면일 때만 되는가, 관망일 때도 되는가"* 를
표본으로 답할 수 있다. **환경 게이트를 켤 가치가 있는지 자체가 채점된다.**

## 4. 그 밖에 눈여겨본 것

- **알림 예산**: *"여기 실린 것이 전부 알림으로 나가지는 않습니다. 도배를 막기 위해
  종목당 한 건, 한 회 다섯 건까지만 발송합니다."* — 봇의 `alert_router.py`가
  같은 일을 하려고 만들어졌는데 `ROUTER_ENABLED=False`로 꺼져 있다. 켤 만하다.
- **김프에 30일 백분위**: 절대값(−0.25%)만으로는 비싼지 싼지 모른다.
  *"최근 범위의 가운데(아래에서 70% 지점)"* 가 있어야 판단이 된다.
  → `kimchi_band.py`로 구현했다 (2차).
- **구조 적합도 0~1**: 추세선을 그리되 *그 선이 가격을 얼마나 설명하는지*를
  같이 낸다. 아무 3점이나 이으면 선은 항상 그려지므로 적합도 없는 추세선은
  의미가 없다. → `grid_lines.py`로 구현했다 (2차).
- **면책 고지가 모든 페이지 하단에 있다.** 친구에게 공유할 계획이면 필요하다.
- **한 마켓만 색이 다르면 그 시장만의 이슈** — 코인·미국·국내를 같이 보는 이유를
  한 줄로 정리한 문장. 봇은 지금 코인 위주라 이 교차 검증이 없다.

## 6. 2차로 만든 것

1차에서 "다음 후보"로 남겼거나, 표에 적어 두고 안 만든 것들이다.

| 파일 | 대응하는 사이트 화면 | 한 일 |
|---|---|---|
| `call_journal.py` | 기록으로 남습니다 | 해시 사슬 발행 기록장 — **고치면 들킨다** |
| `six_bar_align.py` | 리더보드 / 봉 방향 그리드 | 여섯 봉 정렬 + 전환 **시각** + 겹친 종목 |
| `risk_calc.py` | 리스크 관리 계산기 | 손절 거리 기반 크기 · R · 본전 승률 · 켈리 |

| `kimchi_band.py` | 김프 30일 범위 위치 | 절대값이 아니라 위치로 읽기 |

### `call_journal.py`가 왜 표에 없었나

1차 분석 때 이 화면을 '부가 설명'으로 넘겼는데, 다시 보니 **사이트에서
가장 값진 부분**이었다. 지표는 베낄 수 있지만 규율은 구조로 강제해야 한다.

`setup_ledger`가 아무리 정직하게 채점해도, 무엇을 채점 대상에 넣을지를
사후에 고를 수 있으면 표 전체가 무의미해진다. 해시 사슬은 그 구멍을 막는다.

### `six_bar_align.py`와 `regime_gate.py`의 역할 분담

이름이 비슷해 헷갈리기 쉬운데 보는 대상이 다르다.

- `regime_gate` — **시장 전체**가 어느 국면인가. 느린 봉 4개. 진입 게이트.
- `six_bar_align` — **종목 하나**가 어떻게 서 있나. 여섯 봉 전부. 라벨과 후보.

그리고 `regime_gate.detect_turns()`는 어제 스냅샷과 비교해 전환을 세므로
스냅샷이 며칠 쌓여야 한다. `six_bar_align`은 전환을 봉에서 직접 찾아서
오늘 처음 돌려도 나오고, **어느 봉에서 몇 시에** 바뀌었는지까지 나온다.

### 만들면서 고친 것

- 전 봉에 EMA(10, 30)을 쓰면 월봉이 2년 반치 데이터를 요구해서 긴 봉이 영영
  '집계 안 됨'으로 남는다. 그러면 4/6 정렬 자체가 성립하지 않는다 —
  실제로 전 종목이 '방향 갈림'으로 나왔다. 봉마다 창 길이를 달리했다.
- 전환 탐색을 시점마다 EMA 재계산으로 짰더니 전 종목 스캔이 8분 걸렸다.
  EMA가 첫 값에서 출발하는 순수 재귀라는 성질을 쓰면 한 번만 돌려도 된다
  (O(n²) → O(n)). 두 방식의 결과가 같은지는 테스트로 고정해 뒀다.
- 격자를 ±2번선으로 고정했더니 그 밖의 피벗이 전부 '불일치'로 세어져
  규칙적인 사다리조차 적합도 0.4로 탈락했다. 격자는 무한 사다리이고
  화면에 몇 개를 보여 주느냐는 별개 문제다.

## 7. 3차 — 기존 모듈에서 찾은 버그 4건

기능을 더 얹기 전에 1차 모듈을 훑었더니 전부 '조용히 틀린 숫자'가 나왔다.
예외가 안 나는 종류라 테스트를 안 짰으면 계속 몰랐을 것들이다.

| 모듈 | 증상 | 왜 위험한가 |
|---|---|---|
| `level_map.cluster_levels` | 직전 값과 비교해 클러스터가 사슬처럼 이어짐. 0.5%씩 떨어진 피벗 8개(폭 3.6%)가 tol 0.6%인데도 레벨 하나로 뭉침 | `detect_core_signal()`이 레벨 0.5% 이내에서만 발화한다. 레벨이 뭉개지면 신호가 엉뚱한 자리에서 뜬다 |
| `expected_range.check_trade_levels` | 방향을 안 가리고 손절은 항상 하단, 목표는 항상 상단과 비교 | 모듈의 존재 이유가 "위아래 폭이 다르다"인데 숏에서 두 폭을 바꿔 쓰면 경고가 반대로 나온다 |
| `setup_ledger.stats` | 표본 게이트가 보합까지 셈 | "표본 45건"이라 적고 판정 5건짜리 100%를 싣는다. 보합은 분자에도 분모에도 안 들어간다 |
| `setup_ledger.merge` | 사건은 id로 중복 제거되는데 기준선만 가산됨 | 초과 적중률 = 적중률 − 기준선이 이 저장소의 핵심 숫자다. 백필을 두 번 돌리면 표본이 두 배가 된다 |

넷 다 고치고 `tests/test_regressions.py`에 못 박았다. 기준선은 출처(종목|봉)별로
저장해 재실행이 멱등이 되게 했고, 예전 형식 파일도 그대로 읽힌다.

### `healthcheck.py`

같은 종류가 또 들어올 것이므로, **결론 전에 전제를 검사하는 화면**을 뒀다.
사슬 검증 · 기준 변경 이력 · 기준선 표본과 편향 · 셋업 초과값이 자기 오차보다
큰지 · 예상 범위 커버리지를 한 번에 본다.

실제로 돌려 보면 사이트 표와 같은 모양(적중률 82%, 기준선 78%)이 들어왔을 때
`우위 0종 · 잡음 범위 1종 — 지금은 어느 셋업도 시장 방향을 넘어서지 못했습니다`
로 잡힌다. 3절의 논증이 리포트로 자동화된 셈이다.
